Build C and C++ projects with JSON

Slate uses simple JSON files for common CMake workflows. Define your targets and toolchains, then use one CLI to compile, link, run, test, and install with Ninja.

Quickstart Download Slate

Configure, build, and install

Configure targets and toolchains

List modules and select compiler and platform presets in slate.json. In each module.json, declare an executable or library, its sources, and its dependencies. Configure a project.

Build, run, and test

Use slate build to compile and link, slate run --target hello to build and launch an executable, and slate test to run registered tests. Generate and run a build.

Install build outputs

Use slate install --prefix dist to build and install the selected binaries, libraries, headers, and resources. Install targets and components.

Extend the build and test workflow

Use current CLI source builds for CUDA compilation, external test runners, and CMake SDK exports.

Compile CUDA sources

Declare an NVCC executable, select the compute capability, and compile .cu files alongside C and C++. Enable relocatable device code and a device-link step when needed. Configure CUDA.

Run external test suites

Register a script or host tool as a test runner. Reference native fixtures with ${artifact:TARGET} and forward arguments to one selected suite. Declare a test runner.

Export CMake targets

Add install.cmakeTarget to an exported library. Install a relocatable imported target for CMake consumers alongside Slate's SDK metadata. Export a CMake target.

Export and consume an SDK

Build a shared stats library from two modules, then use the installed SDK from a second project with its own slate.json.

Install the stats SDK

The apps project builds stats with a private sum dependency. The install command writes the library, header, and versioned JSON metadata to apps/dist/stats-sdk.

slate install --root apps --target stats --components runtime,dev --prefix dist/stats-sdk

Run stats-demo

The consumer imports stats through libraries. Slate uses the SDK metadata to build and run the program, which prints Mean = 4.0.

slate run --root apps/consumer --target stats-demo

Run both commands from the repository root with Slate v0.1.15 or later. Follow the SDK walkthrough for toolchain setup and manifest details.

Use external tools

CMake

Keep existing CMake scripts. Register cmake under tools and call it with -P from a build task. Declare a task.

vcpkg

Consume packages already installed by vcpkg. Set vcpkgRoot and vcpkgTriplet for the selected toolchain, then declare a dependency with the vcpkg provider. Import a package.

Python

Run Python scripts from preTasks to generate sources or fixtures. List the script and any data it reads as inputs and the generated files as outputs. See the DataBind fixture.

Best practices from salts-utils

Keep project settings in slate.json

List module directories with modules and keep shared defaults in an inherited preset. SaltsUtils includes separate files for platform and tool definitions. View the root manifest.

Keep targets in module.json

Place each manifest beside its sources. The Jinja module includes its own test and benchmark manifests and separates consumer requirements from implementation settings with public and private. View the Jinja manifest.

Track generated files

Give each generated file one producer. The jinja_codegen target declares re2c and Lemon inputs and outputs, and jinja_cmeta lists the generated C files as sources. See the generator tasks.

Manage large projects with coding agents

Understand and edit the build

Codex and other coding agents can trace presets in slate.json and follow dependencies across module.json files. Use the guide for workflows and the reference for valid fields and values. Slate Guide · Manifest Reference

Verify changes

Agents can inspect the resolved dependency graph with slate graph --format json, check the selected toolchain with slate doctor, and confirm which tests are registered with slate test --list. Diagnose and verify.

Manage Slate projects in VS Code and OpenIDEA

Browse projects by workspace directory, then expand each project's Targets branch to see module folders, targets, and source files. Each project keeps its own preset and build directory, including when target names overlap.

VS Code

Open Slate Targets from the Activity Bar. Use the project gear to generate Ninja files, select a preset, and build, run, or test a target. Multiple workspace folders keep their own branches. Install from the Marketplace · Download the VSIX

OpenIDEA

Open the Slate tool window for the same project hierarchy and Codicons. Project rows offer generation and preset selection; target rows offer build, run, and test actions. Colors follow the OpenIDEA theme. Download the OpenIDEA plugin.

Read the editor guide for workspace nesting, icons, presets, and run arguments. Directory-based nesting and the matching OpenIDEA icons are available in current plugin source builds.
